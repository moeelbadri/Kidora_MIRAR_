# Kidora — PHP Edition

نسخة كاملة معاد بناؤها بـ **PHP + قاعدة بيانات حقيقية** (MySQL للإنتاج،
SQLite تلقائي للتجربة السريعة محلياً)، بدل النسخة السابقة القائمة على
JavaScript/localStorage.

## الفيديو المحلي (بدلاً من تضمين يوتيوب)

المشغّلات الآن تستخدم ملفات MP4 محلية فقط، بلا iframe أو اتصال بيوتيوب.
تبقى حقول `youtube_id` معرّفات للمصادر، ويُحفظ الملف المرخّص باسم
`assets/videos/{id}.mp4`. حفظ الرابط في لوحة الأدمن لا ينزّل الملف تلقائياً.
شغّل `php scripts/import-videos.php` لمعرفة الملفات الناقصة، واقرأ
[دليل استيراد الفيديو والنشر](docs/local-videos.md) قبل تفعيل التنزيل.
في Dokploy تُحفظ الفيديوهات على المضيف (مثلاً `/opt/kidora/videos`) وتُربط
داخل الحاوية في `/var/www/html/assets/videos`؛ لا تُرفع إلى Git
ولا تدخل في بناء صورة Docker. خطوات الربط والتحقق موجودة في الدليل أعلاه.
يمكن للأدمن رفع الفيديو ومعاينته واستبداله من تبويب «الفيديوهات» (MP4 / H.264 / AAC، حتى 90 MiB).
يتطلب الرفع ربط المجلد للقراءة والكتابة؛ تضبط صورة Docker صلاحياته عند التشغيل.
المعرّفات مراجع فقط؛ التشغيل محلي عبر Shaka Player المضمّن، والملف المفقود
يعرض رسالة عدم التوفر دون رجوع إلى يوتيوب.

## 🆕 آخر التحديثات (هذه النسخة)
- **الشخصيات بمجلد خاص لكل واحدة**: `assets/images/characters/{slug}/` و
  `assets/audio/characters/{slug}/` — ترفع الصور والأصوات من لوحة الأدمن
  (تبويب 🐾 الشخصيات) وتُحفظ منظّمة تلقائياً. الأدمن الآن يقدر **يعدّل**
  شخصية موجودة بالكامل (الاسم/الصورة/الصوت/الحركة/اللون) مش بس يضيف جديدة.
- **تدفّق ما بعد الدخول**: تسجيل → `welcome.php` (ترحيب + عرض خطط الاشتراك)
  → `assessment.php` (تحليل السلوك) → `tasks.php` (المهام اليومية).
- **تحليل السلوك أصبح 10 أسئلة، ويظهر مرة كل 10 أيام فقط** (وليس يومياً) —
  محفوظ في `children.last_assessment_at`، وتُبنى منه بيانات حقيقية تراكمية
  تظهر بمخطط بالبروفايل ولوحة الأدمن، وتُرسل لولي الأمر عبر واتساب بضغطة زر.
- **كل مهمة الآن تشمل 4 عناصر مربوطة ببعض في جدول واحد**: عنوان ووصف
  يُقرأ بصوت شخصية الطفل تلقائياً، قصة قصيرة عند الإنجاز، فيديو محلي
  اختياري متعلّق بالمهمة، ولعبة قصيرة (`game_type`: التقاط/ذاكرة/سباق
  أسئلة) تظهر فوراً بعد إنجازها قبل الانتقال للمهمة التالية.
- بعد إنجاز باكج المهام، تحويل تلقائي إلى **مكتبة الألعاب** مع اقتراح لعبة اليوم.
- **الرفيق الدائم كبير الآن (~118px) ويمشي فعلياً** يميناً ويساراً عبر
  أسفل الشاشة بحركة مستمرة، بدل شخصية صغيرة ثابتة بالزاوية.
- **المغامرة الكبرى تُبنى من 30 قصة يومية غير مستخدمة**، عند طلب الدمج؛
  لا يشترط أن تكون الأيام متتالية، وتصبح قابلة للمشاركة والتنزيل.
- تصدير الفيديو يحاول الآن صيغة **MP4** أولاً (بحسب دعم متصفحك)، ويعود
  تلقائياً لصيغة WebM إن لم تكن مدعومة.
- بيانات دخول الأدمن الآن: `admin@kidora.com`.

## التشغيل المحلي
```bash
php scripts/migrate.php
php -S localhost:8000 router.php
```
افتح `http://localhost:8000`. تنشئ أداة الترحيل قاعدة SQLite والبيانات الأولية
خارج مجلد الموقع، في `../kidora-private/kidora.sqlite` افتراضياً.
طلبات الويب لا تُنشئ ولا تُرحّل القاعدة؛ تعيد 503 إن غابت الترحيلات.
استخدم `router.php` دائماً مع خادم PHP المحلي لمنع تنزيل الملفات الداخلية.
في Apache يجب تفعيل `AllowOverride All` و`mod_rewrite` لتطبيق `.htaccess`؛
صورة Docker تضبط ذلك. على nginx يلزم حظر config/database/includes/scripts/tests/storage/uploads
والمجلدات المخفية والملفات الخاصة، وعدم تقديم الملفات الداخلية كملفات ثابتة.

## النشر على استضافة حقيقية (MySQL)
1. أنشئ قاعدة بيانات MySQL فارغة، واضبط متغيرات الاتصال أدناه، ثم شغّل
   `php scripts/migrate.php` قبل استقبال الطلبات (لا تستورد schema.sql منفرداً).
2. عدّل `config/config.php`:
   ```php
   define('DB_DRIVER', 'mysql');
   define('DB_HOST', 'localhost');
   define('DB_NAME', 'kidaura');
   define('DB_USER', 'اسم_المستخدم');
   define('DB_PASS', 'كلمة_المرور');
   ```
   (أو عبر متغيرات بيئة `KIDAURA_DB_DRIVER`, `KIDAURA_DB_HOST`... إن كانت الاستضافة تدعمها)
3. اجعل `KIDORA_PRIVATE_DIR` ومجلدات وسائط الشخصيات والفيديو قابلة للكتابة من مستخدم PHP.
4. إن كان المشروع داخل مجلد فرعي (مثال: `example.com/kidaura`)، عدّل `BASE_PATH` في `config/config.php` إلى `/kidaura`.

### ترقية نسخة موجودة وحماية البيانات
- أوقف الطلبات وخذ نسخة احتياطية. اضبط `KIDORA_PRIVATE_DIR` لمسار دائم خارج جذر الموقع.
  شغّل `php scripts/private-storage.php --copy` لنسخ SQLite والوسائط القديمة، ثم
  `php scripts/migrate.php` بالبيئة نفسها. النسخ القديمة لا تُحذف تلقائياً وتظل محظورة عبر HTTP؛
  أزلها من مجلد الموقع بعد فحص النسخة الخاصة. الترحيل يلغي توكنات الدخول القديمة مرة واحدة.
- شغّل الأدوات بمستخدم PHP نفسه، أو اضبط ملكية الملفات له؛ SQLite يُحفظ بصلاحية 600.
- في Docker اربط مجلداً دائماً إلى `/var/www/kidora-private` **قبل النسخ والترحيل**،
  ثم شغّل `docker exec --user www-data CONTAINER php scripts/migrate.php` قبل فتح المرور.
  SQLite لا تُنسخ إلى صورة Docker، ولا صور الأطفال ورسوماتهم.
- اضبط `KIDORA_APP_URL=https://your-domain.example` (مع مسار التطبيق الفرعي إن وُجد).
  روابط الاسترجاع لا تعتمد على Host. خلف وكيل موثوق، ضع عناوينه فقط في
  `KIDORA_TRUSTED_PROXIES` مفصولة بفواصل؛ لا تثق برؤوس جميع الزوار.
- يمكن تعيين `KIDORA_SQLITE_PATH` لمسار خاص بديل. MySQL يستخدم
  `KIDAURA_DB_*`، ويمكن توفير `KIDAURA_MIGRATION_DB_*` منفصلة للترحيل؛
  امنح حساب الويب CRUD فقط دون صلاحيات تغيير الهيكل.
- سياسة الوسائط الافتراضية 365 يوماً (`KIDORA_MEDIA_RETENTION_DAYS`). القراءة تُحظر عند انتهاء
  المدة؛ شغّل يومياً `php scripts/prune-media.php --apply` بمستخدم PHP لحذف الملفات فعلياً.
  بدون `--apply` يعرض العدد فقط. تطبّق السياسة على الوسائط لا نصوص القصص والتقدّم.
  `--include-legacy` يضم أيضاً النسخ القديمة داخل مجلد الموقع بعد فحص الترحيل.
- التسجيل يحتاج تأكيد ولي الأمر. الحسابات القديمة تؤكد من الملف الشخصي قبل رفع وسائط جديدة.
  هذا إقرار بالموافقة، وليس تحققاً من هوية ولي الأمر. راجع السياسة مع مسؤول الخصوصية قبل النشر.
- `media.php` يقدّم الوسائط لصاحبها أو الإدارة فقط، بما فيها الملفات القديمة أثناء نقلها؛
  المشاركة الخارجية تتطلب تنزيل نسخة بدلاً من إرسال رابط خاص. حذف الحساب يحتاج كلمة المرور.

## أهم ما تم بناؤه في هذه النسخة

### 1. الشخصيات — ملاحظة ضرورية
لم أستطع استخدام الشخصيات الكرتونية الشهيرة المطلوبة (سبونج بوب، باتمان،
بيكاتشو، إلخ) لأنها محمية بحقوق ملكية وعلامات تجارية، حتى لو تُرفع الصور
من طرفكم. بدلاً من ذلك بنيت **نظاماً كاملاً قابلاً لرفع صور وأصوات حقيقية**
من لوحة الأدمن (تبويب 🐾 الشخصيات) لأي شخصيات تملكون حقوق استخدامها،
بنفس تجربة العرض والتحريك والثيم المطلوبة تماماً.

### 2. باقة مجانية مقابل باقة مدفوعة (Character Gating)
- أول شخصيتين في القائمة (`is_premium = 0`) متاحتان مجاناً عند التسجيل.
- باقي الشخصيات مقفلة 🔒 وتظهر بشكل باهت حتى يُفعَّل اشتراك مدفوع، عندها
  تُفتح تلقائياً ويمكن للطفل اختيار والتنقل بينها من صفحة "ملفي الشخصي".
- الأدمن يتحكم بأي شخصية مجانية/مدفوعة من زر "تبديل مجاني/مدفوع" في لوحة التحكم.

### 3. تدفّق الاشتراك عبر واتساب (كما طلبت بالضبط)
1. الطفل يسجّل حسابه (شخصيتان مجانيتان + بياناته + رقم واتساب ولي الأمر).
2. يُوجَّه مباشرة لأسئلة تحليل السلوك (`assessment.php`) كلعبة.
3. بعد إنهاء أسئلة اليوم، تظهر خطط الاشتراك المقترحة (بالشيكل ₪).
4. الضغط على "اشترك عبر واتساب" يفتح محادثة واتساب مباشرة على رقمكم
   **+972592038364** (مُعدّ افتراضياً في الإعدادات، وقابل للتغيير من
   تبويب ⚙️ الإعدادات بلوحة الأدمن) برسالة جاهزة تتضمن اسم الطفل والخطة
   وبيانات ولي الأمر، وتُسجَّل الحالة فوراً كـ "قيد المراجعة ⏳" في قاعدة البيانات.
5. الأدمن يرى الطلب في تبويب 💳 الاشتراكات مع رابط واتساب مباشر للتواصل،
   وبعد تأكيد الدفع يدوياً يضغط **"✅ ترقية"** فيتفعّل الاشتراك فوراً،
   تُفتح الشخصيات الإضافية، ويظهر **وسام توثيق ✔️** أزرق بجانب صورة الطفل
   في الناف بار والبروفايل.

### 4. المهام كتحدّيات (باكج 4 مهام يومياً)
- تُختار 4 مهام عشوائياً حسب عمر الطفل.
- بعد إنجاز كل مهمة: تظهر قصة قصيرة مؤثرة إيجابياً + **بطاقة شخصية عربية/
  إسلامية تاريخية حقيقية** (ابن بطوطة، الخوارزمي، ابن سينا، خديجة بنت
  خويلد، شهرزاد، عمر بن الخطاب) مع فيديو محلي قصير إن أضافه الأدمن
  (حقل `youtube_id` في تبويب 🕌 الشخصيات التاريخية بلوحة الأدمن — اتركه
  فارغاً ليظهر أيقونة بدلاً من الفيديو).
- بعد إنهاء الباكج بالكامل، تحويل تلقائي مباشر لصفحة **مكتبة الألعاب**.

### 5. مكتبة الألعاب المصنّفة
ألعاب مقسّمة فعلياً إلى: تربوي، علمي، اجتماعي، سلوكي، ثقافي، صحي.
المكتبة كاملة متاحة للجميع حتى بعد انتهاء التجربة، ولا تُفلتر حسب العمر؛
تتكيف صعوبة اللعب مع عمر الطفل. يدير الأدمن الألعاب وتصنيفاتها.

### 6. الشخصية المرافقة (Companion) عبر كل التطبيق
- إحدى الشخصيتين المختارتين تظهر كفقاعة عائمة ثابتة في كل الصفحات، تتكلم
  بصوت مميز (SpeechSynthesis بنبرة مختلفة لكل شخصية، أو يشغّل الملف
  الصوتي الحقيقي المرفوع لها إن وُجد)، وتوجّه الطفل بجملة سياقية مختلفة
  في كل صفحة (تشجّعه على المهام، تذكّره بزيارة قسم الحماية بعد الألعاب... إلخ).
- خلفية الموقع بالكامل (تدرّج لوني + أيقونات عائمة) تتغيّر حسب لون
  وأيقونات الشخصية النشطة، مع إمكانية تبديل الرفيق بين الشخصيتين.
- زر صوت 🗣️ منفصل عن زر الموسيقى 🔊 في الناف بار.

### 7. القصة اليومية + المغامرة الكبرى
- يكفي إكمال لعبة واحدة اليوم (`STORY_MIN_GAMES = 1`) لفتح توليد قصة اليوم؛
  إنجاز المهام ليس شرطاً، والقصص والألعاب تبقى متاحة بعد انتهاء التجربة.
- رفع صورة الطفل اختياري، والقصة اليومية لوحة واحدة مع سرد صوتي؛ إنجازات
  المهام تثري النص. حلقة التقدم من 30، والدمج عند الطلب لكل 30 قصة يومية
  غير مستخدمة ينتج مغامرة كبرى من ثمانية فصول.
- **تنزيل فيديو حقيقي (MP4 أو WebM بحسب المتصفح)** عبر Canvas + MediaRecorder مباشرة
  من المتصفح، ومشاركة عبر Web Share API — بدون أي خدمة خارجية مدفوعة.
- حقل "مفتاح API لتوليد القصص" جاهز في إعدادات الأدمن لربط خدمة توليد
  فيديو بالذكاء الاصطناعي مستقبلاً إن توفّرت لديكم، دون الحاجة لأي تعديل هيكلي.

### 8. قسم الحماية كتجربة شبه فيديو
كل عنصر توعوي أصبح مَشاهد متحركة متتالية بخلفية متدرّجة وسرد صوتي تلقائي،
بدل نص ثابت — أقرب لتجربة فيديو قصير، بالإضافة للعبة صح/خطأ تفاعلية.

### 9. تحليل السلوك الحقيقي
كل إجابة تُسجَّل فعلياً بقاعدة البيانات (`quiz_history`)، ومخطط التقدّم
(مستوى من 3 لكل محور، وليس نسبة مئوية) يظهر بالبروفايل وصفحة الأسئلة،
مع زر لإرسال تقرير التحليل كاملاً لولي الأمر عبر واتساب.

### 10. لوحة إدارة كاملة (إضافة/تعديل/حذف/ترقية)
- 👨‍👩‍👧 المستخدمون: جدول كامل قابل للفرز (اسم/عمر/نقاط)، بيانات ولي الأمر،
  حالة الاشتراك، وزر عرض التحليل الحقيقي لكل طفل.
- 🐾 الشخصيات: إضافة/حذف/تبديل مجاني↔مدفوع، رفع صورة وصوت حقيقيين.
- 🎯 المهام: إضافة/حذف/تفعيل/تعطيل، فئة عمرية، مرجع فيديو محلي اختياري.
- 🎮 الألعاب: إضافة/حذف، تصنيف حسب المجال والعمر.
- 🕌 الشخصيات التاريخية: إضافة/حذف شخصيات تظهر بعد كل مهمة.
- 💳 الاشتراكات: طلبات معلّقة مع رابط واتساب مباشر، **ترقية/رفض بضغطة
  واحدة**، إضافة/حذف خطط اشتراك، قائمة المشتركين المفعّلين.
- 🏫 المؤسسات: إضافة أدمن مشرف لمؤسسة (مدرسة/جهة شريكة).
- ⚙️ الإعدادات: رقم واتساب المنصة، اسم المنصة، مفتاح API مستقبلي.
- زر خروج يعيد مباشرة للمنصة الرئيسية.

## حدود واقعية (بصراحة تامة)
1. **الرسوم المتحركة** لا تزال سلايدشو متحرك (نص + صور متدرّجة + سرد
   صوتي + Canvas)، وليست جودة استوديو رسوم كاملة، لأن ذلك يحتاج خدمة AI
   مدفوعة غير متوفرة هنا. البنية جاهزة للربط لاحقاً (`story.php`).
2. **واتساب**: رابط `wa.me` يُفتح من المتصفح مباشرة (ليس إرسالاً تلقائياً
   من خادم)، لأن الإرسال الفعلي يحتاج WhatsApp Business API رسمي.
3. **فيديوهات المهام والشخصيات التاريخية محلية**: يُدخل الأدمن مرجع الفيديو
   (حقل `youtube_id`) ويزوّد ملف MP4 مرخّصاً مطابقاً عبر الرفع أو الاستيراد؛
   حفظ المرجع وحده لا ينزّل الفيديو. راجع دليل الفيديو المحلي أعلاه.
4. تأكد من صلاحيات الكتابة على `KIDORA_PRIVATE_DIR`, `assets/images`, `assets/audio`
   على السيرفر الحقيقي حتى تعمل عمليات الرفع من لوحة الأدمن وصفحة القصة.

## الاختبار
المحركات تُحمّل تزامنياً قبل سكربتات الصفحة: `story-player.js` في القصة
اليومية والمغامرة الكبرى والثقافة والأصدقاء والبروفايل فقط، و`games-engine.js`
في المهام ومكتبة الألعاب فقط (ألعاب الذكاء لها تنفيذ مستقل).
جميع ملفات JS/CSS المحلية في الرأس المشترك تستخدم `?v=filemtime` لإبطال
الكاش عند تحديث الملف، بما فيها ملفات مشغّل الفيديو وShaka.

شغّل `python3 tests/integration.py` لاختبارات HTTP المعزولة على SQLite؛
تستخدم قاعدة ومجلد وسائط مؤقتين، ولا تلمس بياناتك. تشمل CSRF والجلسات
والاسترجاع وحدود الدخول والملكية وتزامن مكافآت اليوم والاشتراكات وتحميل المحركات.
MySQL: جهّز قاعدة اختبار فارغة باسم ينتهي بـ `_test` واضبط `KIDAURA_DB_*` ثم
`KIDORA_TEST_MYSQL=1 python3 tests/integration.py`. GitHub Actions يشغّل النسختين.
اختبار رفع الفيديو الفعلي: ابنِ الصورة ثم `bash scripts/test-video-upload.sh IMAGE`.
